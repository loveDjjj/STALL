# 修复记录

本文件只保留影响实验可复现性、运行观察性或吞吐的概略修复。具体代码变更以 Git 提交为准。

## 2026-08-20

- 将每视频严格缓存迁移为按数据集和 split 组织的 32 视频 shard；每个 shard 在读回校验、
  index 原子提交后才删除旧文件，支持安全续跑。
- 增加运行状态、终端日志镜像、命令记录和阶段进度写入；`--dry-run` 不再创建空结果目录。
- 评分改为批量 float64 矩阵计算，默认每批 16 视频；添加逐样本与批量计算一致性测试。
- 修复批量评分时把窗口数误计为视频进度的问题；结果记录数量不受该显示问题影响。
- 发现当前 `/data` 的机械盘读取达到饱和，GPU 利用率受 I/O 限制；保留 packed 顺序读取和
  双卡分片，未用无约束并发进一步争用磁盘。
- 主实验在 GenVideo 评分至 10,608/13,623 时出现两个评分 worker 长时间处于不可中断的
  磁盘 I/O 等待，GPU 已空闲但显存未释放。定位为 packed shard 的 `mmap` 缺页访问与多线程
  读取在机械盘上的组合风险；改为一次完整读入 shard、每个 worker 最多保留两个 shard 的 LRU，
  并将缓存读取线程默认降为 1。这样仍由操作系统使用空闲内存做页缓存，不复制全量数据集。
- 修复双卡评分进度只在 batch 大小恰好整除 1% 阈值时才上报的问题；现按跨过阈值上报，
  `progress.json`、终端和 10 分钟监控记录可持续反映实际评分进度。
- 发现主实验的两级经验 CDF 校准在开发评测分布上存在严重下尾饱和：例如 VideoFeedback 的
  Global 视频分数仅剩 3 个取值，3,498/3,500 个评测视频为 0。追溯到 1024 维经验协方差的
  微小正特征值被白化过度放大，而不是缓存、标签、采样或数据泄漏问题。
- 为白化加入可选 OAS 协方差收缩，主配置显式使用 `method.covariance_estimator: oas`；保留
  `empirical` 仅用于复核旧实现。OAS 仍只拟合 real-only calibration，且不改变 effective-K
  两级 CDF、缓存合同和评测数据划分。真实 VideoFeedback 缓存检查已验证四个白化矩阵均有限。
- 添加病态协方差的 OAS 回归测试；完整测试集目前为 10/10 通过。旧 `alpha_stall` 结果仍标为
  `interrupted` 且不可冻结，后续必须以新配置重新完成评分和 bootstrap。
