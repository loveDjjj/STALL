\section{消融与机制分析}
\label{sec:ablation}

本节将 \method 的主要设计拆解为四个可验证问题：全局 \stall 分支和局部 patch 分支是否互补，局部 patch 似然是否依赖足够真实视频校准，局部二阶时序证据是否优于一阶或更高阶替代，以及局部尺度和聚合方式是否构成跨数据集边界。按照这一证据链，本文把平均结果、生成器级结果、分数分布、真实校准数量、融合权重敏感性和边界实验分别做成表格或图像，避免只用单一平均值支撑机制结论。

\subsection{全局--局部联合分数结构}
原版 \stall 通过空间/时序似然的联合分布展示真实视频和生成视频的分离结构。本文保留这一分析思路，但把横轴设为 global-only \stall 分数，把纵轴设为新增的局部同网格二阶 patch 分数。图~\ref{fig:global_patch_joint} 因而直接检验本文创新点：局部分支是否只是在重复全局分支，还是提供了独立的局部动态证据。

三组数据集均显示 global score 和 patch score 存在正相关，但并非一条单调直线。ComGenVid 上生成视频在两个分支上均明显偏低，说明局部二阶时序证据与全局真实视频校准方向一致；VideoFeedback 和 GenVideo 中存在更多 off-diagonal 样本，表示部分视频由全局分支或局部分支单独捕获。这一结构解释了后续组件消融中的两类现象：融合能提升多数生成器相对 global-only 的性能，但在 patch-only 已经很强的 ComGenVid 上不必然超过 patch-only。

\subsection{全局分支与局部分支互补}

\subsection{真实校准数量与 alpha 微调}
局部 patch 分支通过真实视频估计 patch-level 白化似然，因此其有效性应同时受校准样本数量和真实域代表性影响。为检验这一点，本文在原始主实验数据集和外部小规模数据集上构建互不泄漏的真实视频校准池与 holdout 评测集，并在固定 patch 结构下扫描真实校准数量。表~\ref{tab:real_calib_alpha_summary} 汇总每个数据集的最佳校准规模、global-only、patch-only、固定融合和 best/oracle alpha 结果；图~\ref{fig:real_calib_size_curves} 进一步展示 patch-only AUC 与 best-fusion $\Delta$AUC 随真实校准数量变化的趋势。

\input{tables/real_calib_alpha_summary}

\begin{figure*}[!t]
  \centering
  \includegraphics[width=\textwidth]{real_calib_size_curves.pdf}
  \caption{真实视频校准数量对局部 patch 分支和融合增益的影响。左图为 patch-only 宏平均 AUC；右图为同一 holdout 上 best/oracle alpha 相对 global-only 的 AUC 增益。多数数据集在 25/50 个真实视频时 patch 分支接近随机，100/200/300 个真实视频后才形成可用信号。}

结果显示，真实校准数量不足时局部分支通常不可用。GenVidBench、AIGVDBench、ComGenVid、GenVideo 和 VideoFeedback-small 在 25 或 50 个真实视频校准时均未形成稳定的 patch-only 优势；随着真实校准数量增加，patch-only AUC 在多个数据集上明显上升。例如，GenVideo 从 $n=50$ 的 0.5204 提升到 $n=200$ 的 0.8137，VideoFeedback-small 从 $n=50$ 的 0.6153 提升到 $n=200$ 的 0.7761，AIGVDBench-resplit 从 $n=200$ 的 0.5983 提升到 $n=300$ 的 0.6588。该趋势在修正 AIGVDBench 聚合方式后仍然存在：在 Open-Sora/Pika/Vidu 三源、region3 mean 协议下，$n=25/50$ 的 patch-only AUC/AP 均为 0.5000/0.5000，$n=100$ 仍接近随机，而 $n=300$ 提升到 0.7138/0.7074，并使固定 $\alpha=0.60$ 达到 0.7272/0.7326。该结果支持一个较弱但重要的结论：局部二阶 patch 统计需要足够真实视频来估计稳定的真实域分布；过少真实视频会把 patch 似然退化为接近随机的排序证据。

真实校准数量的收益并不严格单调。ComGenVid 在 $n=800$ 时低于 $n=400$，GenVideo 在 $n=500$ 时低于 $n=200$，VideoFeedback-small 在 $n=500$ 时也低于 $n=200$。这说明校准样本数量是 patch 分支可用性的必要条件，但不是充分条件；真实视频来源、质量噪声和目标真实域覆盖会共同影响校准分布。相应地，本文不把“更多真实视频”写成无条件提升，而将其作为带有代表性要求的校准边界。

  \label{fig:alpha_gain_summary}

融合权重同样呈现数据集相关性。AEGIS-hard 的最佳点接近 patch 主导，ComGenVid 和 GenVideo 的最佳点偏向中等全局权重，VideoFeedback-small 则需要更强 global 主导。为降低测试集 oracle 选择的偏差，我们进一步做了 leave-one-generator-out alpha 选择：每次用其他生成器选择 alpha，再评估留出的生成器。该协议下，ComGenVid 在 $n=200$ 时仍取得 0.8703/0.8854 的 AUC/AP，GenVideo 在 $n=200$ 时取得 0.8484/0.8380，VideoFeedback-small 在 $n=200$ 时取得 0.8649/0.8729，均高于各自 global-only。相反，AIGVDBench-resplit 在 $n=300$ 的默认 region3 bottom-$k$ 设置下，固定 $\alpha=0.60$ 和 best $\alpha=0.65$ 虽分别达到 0.7033/0.7146 与 0.7038/0.7158，但 LOGO 选择降至 0.6801/0.6812，低于 global-only 的 0.6975/0.7070；其 paired bootstrap 相对 global-only 的 95\% CI 也跨 0。后续 region/aggregation 网格显示，该失败主要来自 bottom-$k$ 聚合不适合 AIGVDBench：region3 mean 在固定 $\alpha=0.60$ 下达到 0.7162/0.7278，且相对 global-only 的 paired bootstrap $\Delta$AUC/$\Delta$AP 区间均大于 0。进一步加入 Vidu 第三生成器后，Open-Sora/Pika/Vidu 三源宏平均 global-only 为 0.6994/0.7008，region3 mean 固定 $\alpha=0.60$ 为 0.7272/0.7326，其 paired bootstrap $\Delta$AUC/$\Delta$AP 区间为 [0.0116, 0.0461] 和 [0.0164, 0.0457]。继续加入 CogVideoX1.5 后，四源宏平均 global-only 为 0.6673/0.6633，固定 $\alpha=0.60$ 为 0.6782/0.6832，其 paired bootstrap $\Delta$AUC/$\Delta$AP 区间为 [0.0004, 0.0220] 和 [0.0088, 0.0292]；但 CogVideoX1.5 单源 patch-only 仅 0.4560/0.4764，LOGO alpha 也降至 0.6519/0.6519。该扩展说明 mean 聚合不是只对两源小协议有效，保守固定融合可吸收部分新源负迁移；但跨生成器 alpha 选择仍是明确边界。因此，本文将固定 alpha 视为冻结默认配置，将验证集选择 alpha 作为潜在部署适配策略；测试集 best/oracle alpha 只表示诊断上限，不写成严格部署协议。

表~\ref{tab:validation_fusion_loso} 进一步区分了普通 alpha 微调和三分支权重选择。Alpha-only LOSO 只在 global-only 分数和整体 patch 分数之间选择 $\alpha$，因此对应最小的验证式部署适配；three-branch LOSO 则分别选择 global、spatial patch 和 temporal patch 的非负权重，用于检验空间 patch 与时序 patch 是否值得分开融合。在外部集合上，alpha-only LOSO 已经稳定超过 global-only；three-branch LOSO 在 global\_min\_050 约束下进一步取得 +0.0026 AUC 和 +0.0079 AP 的额外增益，且 paired bootstrap 区间为正。在更保守的 global\_min\_060 约束下，三分支相对 alpha-only 的 AP 仍为正，但 AUC 区间跨 0。原始三数据集上，alpha-only LOSO 已解释几乎全部验证式融合收益，three-branch 相对 alpha-only 的 AUC 增益只有约 +0.0005，AP 约为 0 或略负。该对照使本文的写作边界更清楚：验证式 alpha 选择是当前更稳妥的部署适配策略；三分支拆分提供外部数据集上的潜在优化线索，但尚不足以替代 alpha-only 作为默认方法。

\subsection{局部二阶时序是否必要}
局部时序设计需要同时排除三类替代解释：仅用静态 patch 外观即可、使用一阶相邻差分即可、使用更高阶差分更好。表~\ref{tab:patch_temporal_comprehensive} 因此把 ComGenVid 上的 spatial-only、D=1 lag-1、D=1 multi-lag、motion-hard/soft、D=2、D=3 和 D=4 放在同一协议下比较。D=1 lag-1 的平均 AUC/AP 为 0.8556/0.8617，相对 D=2 下降 0.0718/0.0692；D=3 和 D=4 虽高于一阶替代，但仍低于 D=2。该结果说明当前 patch 分支的主要贡献来自同网格二阶局部动态，而不是简单增加 patch 外观分支或任意提高导数阶数。

关于全局分支的不同导数阶数，当前 release 不应给出未经实验支持的数值。代码层面，patch 分支在 \texttt{src/patch\_matching.py} 和 \texttt{src/eval\_patch\_fast.py} 中显式支持 D=1/2/3/4；global-only 分支则通过原 \stall 参数文件和 \texttt{src/eval.py} 打分，当前没有可直接切换 global temporal order 的命令行参数。因此，全局 D=2/D=3/D=4 不是已有 CSV 的重汇总，而需要重新定义全局时序特征、重建真实视频校准参数并重跑三数据集。本文把全局 \stall 作为固定主干 baseline，把导数阶数消融限定在新增 patch 分支；若审稿要求，可按补充计划扩展 global-order sweep。

\subsection{Patch 似然统计假设诊断}
\stall 原文验证了全局帧特征和归一化一阶帧差分在白化后近似满足高斯似然建模所需的统计条件。由于本文把同一套真实视频白化高斯似然扩展到 patch token、局部 region-pooled token 和归一化二阶 patch 差分，我们补充了对应的统计诊断。该实验使用 ComGenVid 真实视频 patch cache 抽样 256 个视频，每种表示最多抽取约 5 万行；诊断量包括坐标级 Anderson--Darling (AD) 与 D'Agostino--Pearson (DP) 正态性压力测试、白化后 covariance 与单位阵的接近程度、白化方向余弦分布，以及不同 patch/region 位置共享同一个 $\mu,W$ 时的残余差异。这里 patch token 和二阶 patch 差分使用 release 中真实视频拟合的 $\mu,W$；region-pooled token 是二阶差分前的中间表示，不作为独立最终分支，因此只使用随机 half-split diagnostic whitening 做假设审计。

表~\ref{tab:patch_likelihood_assumption_audit} 和图~\ref{fig:patch_likelihood_assumption_audit} 显示，归一化二阶 patch 差分是三类表示中最符合建模假设的一类：其白化 covariance diagonal mean 为 0.975，off-diagonal RMS 为 0.009，AD pass@5\% 与 DP $p>0.01$ 分别为 0.883 和 0.906，方向余弦标准差 0.0319 接近 1024 维球面期望 0.0312。相比之下，raw patch token 和 region-pooled token 的 covariance 与方向余弦仍接近球形化目标，但坐标级正态性通过率较低，且不同位置的白化范数残差更大。该结果支持本文把主要创新落在局部二阶时序分支，而不是单纯依赖 patch 外观似然；同时也提示，若后续进一步提高 patch 空间分支权重，per-position 或分层位置校准可能比单一共享 $\mu,W$ 更稳健。

\subsection{局部尺度、聚合方式与跨数据集边界}
局部异常的空间支持域决定 patch 证据是捕获小范围纹理/运动异常，还是被较大区域的平均效应稀释。表~\ref{tab:hyperparameter_sensitivity_matrix} 汇总 region size、aggregation 和 bottom-$k$ ratio 的多数据集敏感性。ComGenVid 在 region=3 mean 下取得最高 region-family AUC，VideoFeedback 在 region=1 mean 下最好，GenVideo 的最优 mean 设置为 region=2。aggregation 也呈现同样边界：GenVideo 和 VideoFeedback 上 mean 优于 bottom-$k$，而 ComGenVid 中增大 bottom-$k$ ratio 可继续提升 patch-only AUC。

\subsection{时间窗口、覆盖缺口与计算代价}
表~\ref{tab:runtime_window_boundary} 将时间窗口和计算/存储边界集中报告。为对齐 \stall 原文附录中的 temporal setting 分析，本文补充了 ComGenVid 1 秒代表性窗口实验。该实验只评测 patch-only 分支，因为当前资产没有匹配的 1 秒 global score；在同网格二阶、region=3、bottom-$k=0.20$ 的设置下，1 秒窗口取得 0.9434/0.9456 的 AUC/AP，高于 2 秒 patch-only 主线的 0.9273/0.9309。该结果说明局部二阶时序证据不严格依赖较长窗口，但由于只在 ComGenVid 上实跑，本文将其作为代表性边界证据，而不是三数据集鲁棒性结论。

当前 release 还记录了 patch 覆盖缺口：VideoFeedback 的 Hotshot-XL、GenVideo 的 HotShot-XL 和 MoonValley 未纳入主线 patch baseline，原因是短视频 duration mismatch 或缺少 patch score 资产。因此，VideoFeedback 主线覆盖 10 个 2 秒来源，GenVideo 主线覆盖 8 个来源。该边界应保留在主文脚注或补充材料中，避免把主线均值误写为覆盖所有原始来源。计算代价方面，compact patch cache 是主要存储成本；debug-2 clean-cache benchmark 只代表阶段成本，不能线性外推为全数据集端到端耗时。
